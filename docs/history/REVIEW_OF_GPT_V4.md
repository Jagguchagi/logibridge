# What this final version took from GPT v4, and what it changed

GPT v4 was read from its snapshot file (LogiEdge_GPT_v4_NEXT_CHAT_SOURCE_SNAPSHOT). It was not modified.

## Problems found in v4
| Problem | Effect | Fixed here |
|---|---|---|
| RUN_ID required by the service; playbook hard-codes demo01; simulator refuses to reuse an id | New runs are silently ignored by a deployed container; plain `docker run` crashes | RUN_ID optional (latches first run), playbook variable, warning when another run is ignored |
| No demo backend; playbook passes no BACKEND_URL | Offline store-and-forward cannot be demonstrated | inference/backend_demo.py; BACKEND_URL in playbook |
| About half the planned scripts missing (selection, PSI/SLA analysis, Ansible double run, OTA savings, smoke test) | Several brief tasks have no evidence path | All present in scripts/ |
| 10 tests | No coverage of playbook, Dockerfile, service, analysers | 32 tests |
| No architecture image; brief file names replaced | A2 and repo-structure gaps | system_architecture.png and brief names |
| Pareto chart not annotated; no stale-result check | F2/F3 weaker | Annotated frontier; hash-checked selection |
| Docs with words run together | Hard to read or reuse | Rewritten |
| Single JSONL snapshot with base64 data | Did not open reliably in a new chat | NEXT_CHAT_SOURCE.md: plain text source; data regenerated by script |

## Adopted from v4
Requirements table from the actual brief; drift monitor rejecting missing/mismatched model and stats hashes; run and truck ids on every message; 4-window purge; bounded buffers with gap reset; pruning that stops instead of silently switching method; an honest coverage list.

## Not adopted
Max-probability as the default PSI score (kept P(Normal), both logged, disclosed); mandatory RUN_ID; the reduced tooling and tests.
